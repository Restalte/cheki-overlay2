# CHEKI STUDIO（登録不要・複数スタジオ版）

## この版の仕様

- 会員登録・ログイン不要
- トップページの「スタジオを作成する」から専用スタジオを発行
- スタジオごとにチェキデザイン、TikTokユーザーID、ギフト条件、接続状態を分離
- 管理用URLとOBS表示用URLを別々に発行
- ギフト受信時は、そのスタジオに登録されたチェキだけをランダム表示
- アルバム・自動撮影機能は削除
- Eulerstreamなどの有料署名サービスを使用しない無料接続方式

## 必要環境

- Node.js 22.19.0以上
- npm
- インターネット接続

## ローカル起動

```bash
npm install
# Supabaseの接続情報を .env に設定してから起動
npm run dev
```

ブラウザで `http://localhost:5173/` を開き、「スタジオを作成する」を押してください。

## スタジオURLの取り扱い

作成後、管理用URLとOBS用URLが発行されます。

- 管理用URL：チェキデザインやTikTok接続を変更できる秘密URL。第三者に共有しないでください。
- OBS用URL：オーバーレイ表示専用URL。OBSのブラウザソースに登録します。

管理用URLには操作権限を持つ秘密キーが含まれます。紛失するとそのスタジオの管理画面へ戻れなくなるため、必ずブックマーク等で保存してください。ログインやパスワード再発行機能はありません。

## OBS設定

1. スタジオ管理画面の「オーバーレイを開く」を押します。
2. 表示されたOBS用URLをコピーします。
3. OBSの「ブラウザ」ソースに貼り付けます。
4. 配信キャンバスに合わせて幅・高さを設定します（例：1920×1080）。

OBSは各利用者のPC上で動作します。公開サーバーから利用者のPCのOBSを直接操作する機能はありません。オーバーレイはOBSのブラウザソースで表示します。

## TikTok LIVE設定

1. 管理画面に配信者のTikTokユーザーIDを入力します（@は不要）。
2. 反応対象を「すべてのギフト」または「指定したギフトのみ」に設定します。
3. 「TikTokに接続する」を押します。
4. チェキを登録し、テストギフトで動作確認します。

ギフト一覧は公開されている日本向けカタログを参照します。TikTok公式APIではなく、掲載内容・ギフトID・価格の最新性は保証されません。無料接続ライブラリも非公式であり、TikTok側の仕様変更で接続できなくなる場合があります。

## 公開サーバーへの配置

このアプリはNode.jsサーバーでTikTok LIVEとのWebSocket接続を維持します。スタジオ情報はSupabase Database、チェキ画像はSupabase Storageへ保存するため、Renderの一時ファイル領域には依存しません。

公開する場合は、次の条件を満たすホスティング先を使用してください。

- Node.js 22.19.0以上を実行できる
- `npm run build` の後に `npm start` を実行できる
- `PORT` 環境変数に対応
- WebSocket接続を許可している
- 長時間の常時稼働が可能

Render無料環境がスリープするとTikTok LIVE接続は切断され、復帰後に再接続します。スタジオ情報とチェキ画像はSupabaseに保存されます。Supabase無料枠には容量・利用条件があるため、重要データは定期バックアップしてください。

ビルド・起動コマンド：

```bash
npm install
npm run build
npm start
```

Supabaseの `cheki_studios` テーブル、`cheki_items` テーブル、および `cheki-images` Storage bucket を使用します。Renderのファイル領域にはチェキ本体を保存しません。

## 以前のチェキデータについて

元のローカル版に保存されていた `data/chekis.json` は `data/legacy-chekis-backup.json` として同梱しています。新しい専用スタジオには自動では混ぜていません。これは利用者全員に以前の管理者のチェキが見えてしまうのを防ぐためです。既存デザインを引き継ぐ場合は、バックアップを手元に保管し、必要なスタジオへ個別に登録してください。

## 保存データ

- Supabase `cheki_studios`：スタジオごとの管理キー、表示キー、TikTok設定
- Supabase `cheki_items`：チェキ名・画像ファイルの保存先・登録日時
- Supabase Storage `cheki-images`：チェキPNG画像
- `data/tiktok-gifts.json`：全スタジオ共通の公開ギフトカタログキャッシュ（再取得可能な一時キャッシュ）

各スタジオのAPIは管理キーで保護され、OBS用WebSocketは表示キーで保護されます。管理用URLは秘密情報として扱ってください。

## 注意

- 登録不要のため、管理用URLを忘れた場合の本人確認・復旧機能はありません。
- 利用者が増えると、1台のサーバーで維持するTikTok接続数・メモリ・通信量が増えます。接続数に上限を設ける運用が必要です。
- Supabase無料枠の上限やプロジェクトの停止・削除など、外部サービス側の条件により保存が利用できなくなる可能性はあります。絶対的な無期限保存を保証するものではありません。
- ギフト接続は非公式方式です。完全無料を優先する代わりに、TikTok側の仕様変更による停止リスクがあります。


## Supabaseへの保存設定（必須）

1. Supabaseで新しいプロジェクトを作成します。
2. DashboardのSQL Editorを開き、同梱の `supabase-schema.sql` を全て実行します。
3. Project Settings > API から Project URL と `service_role` key を取得します。
4. RenderのEnvironmentに次の3つを登録します。
   - `SUPABASE_URL`：Project URL
   - `SUPABASE_SERVICE_ROLE_KEY`：service_role key（秘密情報。GitHubやブラウザ側へ絶対に置かない）
   - `SUPABASE_STORAGE_BUCKET`：`cheki-images`
5. 保存して再デプロイします。

サーバーは起動時にSupabaseから全スタジオとチェキ一覧を読み込みます。チェキ保存時は画像をStorageへアップロードし、DBに情報を登録した後、DBから保存結果を再取得して一致を確認してから成功を返します。Supabaseの接続情報やテーブル・Bucketが正しくない場合はサーバー起動または保存がエラーになり、成功扱いにはしません。

ローカルの `.env` を使う場合は `.env.example` をコピーして値を設定してください。`.env` はGitHubへアップロードしないでください。
